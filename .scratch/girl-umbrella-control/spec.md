# 規格：操作少女在便利商店場景移動，依所在區域開傘與收傘

> 搬自少女實驗專案。文中提到的 `screenshots/` 驗收截圖與拍攝腳本沒有帶入。

Status: ready-for-agent

這份規格取代同一個議題追蹤系統裡舊的「二次元少女在雨夜便利商店場景中走動」規格。舊規格的自動巡行改成玩家操作，載入角色、程式驅動骨骼、融入場景風格的要求沿用，並整理進本文，不必再回頭讀舊規格。

## 問題陳述

便利商店場景目前只有建築與天氣，沒有任何人物。使用者想研究的是：在微縮場景裡操作一位二次元少女，看她走路、跑步、撐著透明傘、走進店裡把傘收起、出門再把傘撐開，這些動作能不能做得自然。

這個專案是原專案的實驗複本，目的只在研究少女的操作與動作，場景本身不需要再打磨。使用者確認成果滿意之後，會把這次的成果合併回原專案。

## 解決方案

在便利商店場景加入少女。玩家用 WASD 操作她移動，按住 Shift 跑步。開場維持原本的俯瞰視角，按 `C` 切到貼在少女背後的跟拍視角，可以近距離看動作。

少女手上拿著程式產生的透明傘。下雨或下雪時，她在露天會撐開傘，走進雨棚下就收傘，進到店內時傘已經收起；從店內走出到雨棚下就開傘，走回露天時傘已經撐開。晴天時傘一律收起。她靠近自動門時門會打開。撐開的傘下面不會有雨絲或雪花穿過。

## 實作決策

### 模組

**少女行為**：一個不依賴 three.js、不碰畫面的純邏輯模組，是這次唯一的測試接縫。對外只有一個每格呼叫的更新函式，接收目前狀態、這一格的輸入、場景資訊與經過時間，回傳下一格的狀態。

- 輸入：移動方向（WASD 組合成的向量）、是否按住 Shift、相機的水平朝向。
- 場景資訊：目前天氣，以及店面配置。
- 狀態：位置、地面高度、面向、目前速度、動作（待機、走路、跑步）與各動作的混合權重、步伐相位、所在區域、上一個非雨棚下的區域、傘的張開程度（0 是收起、1 是撐開）、自動門是否該打開。
- 另外提供建立初始狀態的函式，出場位置在店前人行道的露天處；下雨或下雪時初始狀態的傘已經是撐開的。

**店面配置**：描述便利商店場景可走範圍的資料，由少女行為讀取，測試也用同一份真實資料。內容包括：

- 區域：店內是自動門以內的店面，大約 x 從 -6 到 4、z 從 -6 到 1；雨棚下是店門前那一條，大約 x 從 -6.2 到 4.3、z 從 1.0 到 2.35，以及店右側那一段，大約 x 從 4.0 到 5.1、z 從 -2.85 到 1.05；其餘可走的地方是露天。數值以場景建模程式為準，實作時要讀過店面外觀、店內與底座的程式後再確認。
- 可走範圍：店內、雨棚下、店前人行道與停車區。馬路不可走。
- 障礙物：牆、玻璃、櫃子、收銀台、貨架、自動販賣機、自行車、傘架等，以平面上的方框表示。店面正面除了自動門那一段之外都是玻璃牆，不可穿越。
- 地面高度：店內地板比外面高約 0.12 公尺。
- 自動門感應區：門前後一小段範圍。

**少女外觀**：載入 VRM 檔、處理朝向、套用材質與描邊、每格依少女行為的狀態驅動骨骼，並更新 three-vrm。

**透明傘**：程式產生的透明塑膠傘，傘骨與傘面的開合由傘的張開程度驅動，掛在少女右手的骨骼上。

**少女相機**：管理俯瞰視角與跟拍視角的切換、跟拍時的繞轉、距離、自動回到背後與碰撞拉近。

**少女輸入**：讀取 WASD、Shift、`C` 的按鍵狀態，在輸入焦點位於面板元件或場景選單開著時忽略移動鍵。

### 傘的規則

每格先決定傘的目標狀態，再讓張開程度以每 0.8 秒走完全程的速率朝目標移動，所以半途掉頭時會從當下的程度自然反轉。

- 天氣是晴：目標是收起。
- 天氣是雨或雪：
  - 在露天：目標是撐開。
  - 在店內：目標是收起。
  - 在雨棚下：看少女是從哪裡進入雨棚下的。從露天進來，目標是收起；從店內出來，目標是撐開。判斷依據是「上一個非雨棚下的區域」。
- 張開程度介於 0 與 1 之間時，移動速度乘上一個減速係數，讓開收傘時腳步稍微放慢。
- 天氣以目前選定的天氣為準，不看雨量漸變的程度，所以切換天氣後她會立刻開始開傘或收傘。

### 移動

- 移動方向由輸入向量依相機水平朝向旋轉而得，斜向時先正規化。
- 速度朝目標速度平滑加減速。走路約每秒 1.3 公尺，跑步約每秒 3 公尺，實際數值依畫面調整。
- 面向以有上限的角速度轉向移動方向。
- 與障礙物碰撞時沿著障礙物的邊滑開，不會卡死；走到可走範圍邊界時停在邊界上。
- 步伐相位依實際移動距離推進，步幅由腿長推算，確保腳不滑。

### 動作與骨骼

- 不引入外部動畫檔，用程式直接旋轉 VRM 的正規化人形骨骼。理由沿用舊規格：現成走路動畫的授權不明，Mixamo 需要登入 Adobe 帳號才能下載。日後要換成外部動畫，另開議題，由使用者自行下載。
- VRM 預設是 T 字站姿，手臂要先放下，再疊加擺動。
- 待機、走路、跑步各自產生一組骨骼姿勢，依少女行為給的混合權重疊加。
- 拿傘姿勢疊在步態之上，只影響右臂。撐開時右臂把傘舉在頭上偏右；收起時右臂下垂，傘尖朝下；開收傘的過程依張開程度在兩者之間內插。左臂照步態擺動。
- 撐開的傘依步伐相位輕晃，跑步時往前傾。

### 相機

- 開場是原本的俯瞰視角，行為與現在完全相同，不跟隨少女。
- 按 `C` 時，相機約一秒內平滑飛到另一種視角。
- 跟拍視角：繞轉中心在少女胸口高度；左鍵拖曳繞轉；滾輪距離限制在約 1.5 到 6 公尺；停用右鍵平移。使用者沒有拖曳、且少女已移動一會兒時，相機水平角度慢慢轉回她背後。
- 碰撞：從繞轉中心往相機方向做檢查，被店面配置裡的牆或物件擋住時，相機拉近到擋住的位置前方；在店內時相機高度壓在天花板以下，天花板高約 2.98 公尺。
- 現有渲染流程每格會把相機中心限制在底座範圍內，切到跟拍視角時要確認這個限制不會和跟隨衝突。相機拉得很近時，要確認近裁切面不會切掉少女。

### 雨雪遮擋

- 共用引擎的雨絲與雪花加上一個「傘」的遮擋參數：傘的位置與半徑。傘下方圓柱範圍內的雨絲與雪花不畫。
- 只有傘撐開時才生效，遮擋的強度跟著張開程度。沒有少女的場景不傳這個參數，畫面和現在一樣。

### 自動門

- 少女行為在少女進入感應區時回報「門該打開」，場景的自動門動畫讀取這個訊號，打開並維持開啟，直到少女離開感應區後再關上。
- 少女不在附近時，原本每 9 到 16 秒隨機開關一次的節奏保留。由少女觸發開門時，一樣發出原本的開門音效事件。
- 自動門開啟到能通過之前，門那一段在店面配置裡仍是障礙物。

### 按鍵

- 新增：WASD 移動、Shift 跑步、`C` 切換視角。
- 移除共用介面中 `W` 切換天氣與 `S` 開關聲音這兩個快捷鍵，不另外綁新鍵。天氣面板與聲音按鈕仍可用滑鼠操作。溫泉旅館會一併受影響，這是可以接受的。
- 其他按鍵維持原狀，包括 `←` `→` 調時間、`M` 開選單、`1` 到 `9` 切場景、`-` `+` 調音量。
- 移動鍵以實體按鍵位置判斷，避免輸入法或大小寫影響。

### 載入與融入場景

- three-vrm 以 import map 從 CDN 引入，網址鎖定完整版本號，版本要與 three 0.160.0 相容。動手前先查該版本的相依說明，並確認它內部匯入 three 時走 import map，不會自己打包一份 three，否則會有兩份 three 實例，材質與骨骼會壞掉。
- VRM 檔是 0.x 格式，預設朝向和 1.0 不同，載入後要轉正，讓臉朝移動方向。身高約 1.5 到 1.65 公尺，對照店門與自動販賣機確認比例。
- 少女非同步載入，不阻擋開場布幕；載入失敗時只在主控台留下訊息，場景照常運作，少女行為與相機也不啟用。
- 少女與透明傘必須在靜態網格合併之後才加入場景，或標記為不參與合併，否則會被併進地形。
- 每格更新使用場景既有的每格登錄機制，不另開動畫迴圈。
- 場景用五階色調的三渲二材質加上背面擴張法描邊。引擎內建的描邊用包圍盒放大，不適用於有骨骼的網格，改用 three-vrm 材質自帶的描邊，或另寫適用於蒙皮網格的做法。
- VRM 材質的受光方式和場景不同，要調整到在冷色月光、便利商店暖光、白天、雪景下都和場景一致。
- 地面濕地的反射用圖層區分，描邊走圖層 1 且不進反射。少女本體要出現在倒影裡，描邊殼不要。
- 少女要投影，也要接收屋簷與招牌的光。
- 引入 three-vrm 時，到該套件的儲存庫確認授權條款並補記到角色資產的標註文件，不要憑印象寫。

## 測試決策

### 什麼是好測試

- 只透過少女行為的更新函式測試外部行為：給定狀態、輸入、天氣、經過時間，檢查回傳的位置、動作、所在區域、傘的張開程度、門的訊號。
- 不測試骨骼角度、混合權重的確切數值、速度常數本身這類實作細節。數值調整後測試不該壞掉，例如只檢查「跑步比走路快」、「傘在 1 秒內從收起變成撐開」，不檢查確切速度。
- 測試使用真實的店面配置資料，不另造假的地圖，這樣配置改錯時測試會抓到。

### 要測的模組

只有少女行為，連同它讀取的店面配置。測試案例至少涵蓋：

1. 初始狀態在露天；雨天、雪天時傘是撐開的，晴天是收起的。
2. 相機朝向不同時，同一個 W 輸入會往不同的世界方向移動。
3. 斜向移動的速度與直走相同。
4. 按住 Shift 後穩定速度比走路快；放開所有鍵後速度降到零，動作回到待機。
5. 朝牆或障礙物持續移動不會穿過去；斜向撞牆時會沿著牆滑動。
6. 朝馬路持續移動會停在可走範圍邊界。
7. 從露天走到店內的路上：進入雨棚下後傘開始收，抵達店內前或抵達時傘已收起。
8. 從店內走到露天的路上：進入雨棚下後傘開始開，抵達露天前或抵達時傘已撐開。
9. 收傘到一半時掉頭走回露天，張開程度從當下的值開始回升，不會跳回 0 或 1。
10. 開收傘期間的移動速度比平常慢。
11. 晴天時，無論在哪個區域傘都是收起的。
12. 在露天時天氣從晴變雨，傘開始撐開；從雨變晴，傘開始收起。
13. 少女進入自動門感應區時回報門該打開，離開後回報門該關上。
14. 店內的地面高度比露天高。

測試以 Bun 內建的測試工具執行，不需要安裝套件。在專案設定裡加上執行測試的指令。

### 先例

程式碼庫目前沒有任何測試，這會是第一組。可以參考的是專案裡現有的純函式寫法，像溫泉旅館用來查詢地面高度的地形函式，它也是不依賴畫面、由多處呼叫的純邏輯。

### 瀏覽器驗收

骨骼動作、相機手感、傘的外觀、風格融合、倒影、雨雪遮擋無法用自動測試確認，要用 `bun start` 開啟場景實際檢查：

1. 場景正常載入，主控台沒有錯誤。
2. 少女站在店前人行道，比例協調，腳踩在地上。
3. WASD 移動、Shift 跑步、轉向、停下都自然，肉眼看不到腳滑與骨骼扭曲。
4. 雨天從露天走進店內，傘在雨棚下收起；從店內走出，傘在雨棚下撐開。開收過程看得到傘骨開合與手臂動作。
5. 跟拍視角下，撐開的傘下面沒有雨絲或雪花。
6. `C` 切換視角平滑；跟拍時可繞轉與縮放，相機不穿牆，店內不穿出天花板。
7. 少女走近自動門時門會打開。
8. 晚上、傍晚、白天與雨、雪下，少女的亮度與色調和場景一致。
9. 地面倒影中看得到少女。
10. 切換到溫泉旅館再切回來，少女不重複也不殘留。
11. 故意讓 VRM 載入失敗，場景仍正常顯示。
12. 畫面更新率在一般筆電上沒有明顯下降。

## 不在範圍內

- 手機與觸控操作；手機上少女只會待機。
- 腳步聲、開傘與收傘的聲音。
- 即時調整動作參數的調校面板、慢動作、畫面上顯示區域與傘狀態的輔助資訊。
- README 的修改，之後會整份重寫。
- 溫泉旅館場景的少女；它只會受到移除 `W`、`S` 快捷鍵的影響。
- 雨滴打在傘面濺開、少女被雨淋濕。
- 多個路人、過馬路、與車流互動。
- 外部動畫檔、換用其他角色模型。
- 導航網格或第三方尋路。
- 場景本身的打磨。
