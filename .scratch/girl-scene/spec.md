# 少女場景：把少女實驗併入主專案，成為第三個場景

Status: ready-for-agent

## 問題陳述

主專案目前有兩個場景：雨夜便利商店與秋夜紅葉屋。另有一個獨立的實驗專案，是主專案的完整複本，在雨夜便利商店裡加入一位由玩家操作的少女，會依所在位置撐開或收起透明傘。

這兩個專案現在各自存在、沒有共同的 git 歷史，也沒有遠端。實驗成果只能在實驗專案裡看，無法從主專案的場景選單進入；兩邊的引擎與街景程式還在持續分叉，越拖越難合併。

## 解決方案

把有少女的便利商店作為主專案的第三個場景。使用者從場景選單就能進入，選單順序為便利商店、少女場景、紅葉屋。

- 原本的便利商店與紅葉屋維持現狀，畫面、聲音與快捷鍵都不受影響。
- 少女場景沿用便利商店的街景、天氣與聲音，並加上由玩家操作的少女、透明傘、俯瞰視角與跟拍視角。
- 實驗專案在合併後停止開發，主專案成為唯一來源。

27. 身為維護者，我想要少女模型與外部套件的授權說明隨資產一起進入主專案，以便合乎授權要求。

## 實作決策

**場景身分與目錄**

- 新場景的識別為 `girl`，有自己的頁面，沿用現有的一個頁面一個入口的多頁面架構。
- 場景目錄新增一筆資料，選單順序為便利商店、少女場景、紅葉屋。標題與說明由實作者擬定，風格與現有兩筆一致。標題的建議方向是在便利商店名稱後加上少女與傘的描述。
- 開場時間與天氣沿用便利商店：二十三點、雨。
- 縮圖由實作者啟動場景後截圖產生，規格與現有縮圖一致。
- 場景目錄的每筆資料新增「是否佔用 WASD」的宣告欄位，只有少女場景為真。

**街景共用**

- 把便利商店場景的建立流程抽成一個共用函式，內容包含環境設定、各建模模組、靜態合併、天氣表面、主迴圈與就緒事件。
- 原便利商店與少女場景各自有一個薄入口，呼叫這個共用函式。少女場景的入口額外負責建立少女。
- 夜間店內燈光壓到兩成亮度，店內商品改為受光材質而非自發光；原便利商店與少女場景共用同一個版本，不再另有選項。
- 少女的非同步載入不能阻擋場景開場，載入失敗只在主控台警告。

**引擎層與街景模組的共用修改**

以下修改已確認對沒有少女的場景零影響，直接帶入主專案，兩個場景共用：

- 雜湊函式改為對外匯出。
- 雨雪粒子支援傘遮擋；沒有設定遮擋時等同沒有遮擋。
- 渲染器提供預編譯功能，並且只在相機控制啟用時才套用平移範圍限制。
- 街景各處發出事件的鉤子，在沒有人監聽時不做事。
- 自動門暴露「想要開門」與「開啟程度」兩個狀態；沒有人要求時，開關節奏與亂數序列都和原本一致。
- 便利商店聲音改成店內濾波連續追蹤門的開啟程度，並新增關門音。這會使原便利商店的聽感略有不同，已確認接受。

**快捷鍵**

- W 切換天氣與 S 開關聲音，改為由場景宣告是否佔用 WASD 來決定是否綁定。
- 場景選單、天氣與時間面板、聲音面板、音訊引擎都要依這個宣告決定是否啟用該快捷鍵，並同步決定說明列與按鈕提示是否顯示該鍵。
- 少女場景中天氣與聲音只能用滑鼠操作；便利商店與紅葉屋維持現狀。

**少女模組**

- 少女的全部模組、事件模組、遮擋模組及其測試，搬到專案內獨立於便利商店的區域，並與原便利商店的建模模組分開。
- 少女的店面配置沿用硬編碼座標，與建模端的同步問題先接受現狀，不在這次重構。
- 搬入時換行符統一為 LF。

**資產、套件與部署**

- 少女的 VRM 模型直接放進倉庫的資產區，附上授權說明。
- 少女頁面的 importmap 加入 VRM 套件，從 CDN 載入，維持原版本。
- 部署流程的複製清單加入新頁面與角色資產。
- 套件加入 `bun test` 指令。

**文件與議題**

- 少女專案的詞彙表帶到主專案根目錄；由於它描述的是「便利商店場景加少女」，帶入時把開頭的專案描述改成涵蓋三個場景。
- 少女專案三個已結束功能的規格與票券文字帶入議題目錄，不帶驗收截圖與拍攝腳本。進行中的「第二輪使用者驗收」票維持未完成狀態。
- 說明文件補上第三個場景、操作方式，並移除「所有模型、貼圖和動畫都由程式產生」的過時敘述。

## 測試決策

**好測試的標準**：只透過公開的外部行為驗證，不測試實作細節；使用真實的店面配置與真實的場景目錄，不用替身。

**接縫一：少女行為，既有**

- 入口是建立少女初始狀態、每格更新少女狀態這兩個函式，以及跟拍相機避牆函式。
- 搬進主專案後，既有的行為測試與跟拍相機測試必須原封不動通過，只允許因模組位置改變而調整匯入路徑。
- 先例就是這兩組既有測試，使用 `bun:test`，風格是描述使用者可見的行為。

**接縫二：場景目錄契約，新增**

- 入口是場景目錄這份資料，加上它所指向的檔案系統與部署設定。
- 要驗證的行為：
  - 目錄共有三個場景，識別不重複。
  - 每個場景的頁面檔與縮圖檔都存在。
  - 部署流程的複製清單涵蓋每個場景的頁面與資產。
  - 只有少女場景宣告佔用 WASD。
  - 選單順序是便利商店、少女場景、紅葉屋。
- 先例：沒有直接先例，風格比照既有測試。

**手動驗收**（渲染與互動沒有自動接縫，不為此建立截圖比對設施）

- 原便利商店：夜晚店內是壓低後的亮度，商品受光；畫面無異常。
- 原便利商店：店內聲音與門的聽感，確認可接受。
- 紅葉屋：畫面與聲音無異常；W 與 S 快捷鍵仍可用。
- 便利商店：W 與 S 快捷鍵仍可用，說明列仍顯示。
- 少女場景：WASD、Shift、C 視角切換、開傘與收傘、自動門、傘遮擋雨雪、夜間店內不暈光。
- 少女場景：W 與 S 不觸發天氣與聲音切換，說明列不顯示這兩鍵，滑鼠操作正常。
- 少女場景：模擬模型載入失敗，場景仍正常顯示。
- 三個場景之間的切換、轉場布幕與環境音接續。

## 不在範圍內

- 程式生成待機、手指與臉的效果改進。
- 少女專案「第二輪使用者驗收」票本身的驗收。
- 單頁多場景的重構，包含場景釋放與全域單例重置。
- 把少女店面配置的硬編碼座標改成從建模端讀取。
- 合併實驗專案的 git 歷史、驗收截圖與拍攝腳本。
- 實驗專案資料夾的任何後續維護。
- 為渲染畫面建立自動截圖比對。

## 補充說明

- 實驗專案是主專案在合併前某個時間點的複本，兩邊的差異已逐檔比對過：引擎層與街景模組的修改是為少女加的鉤子，除了夜晚店內亮度與店內聲音兩處，其餘在沒有少女時零影響；夜晚店內亮度已決定兩個便利商店場景統一採用壓低後的版本。
- 實驗專案目前在 `dev` 分支，另有 `main` 與 `natural-idle` 兩個分支；`natural-idle` 沒有獨有的 commit，搬遷以 `dev` 的最新狀態為準。
- 實驗專案的檔案多為 CRLF，主專案為 LF，比對與搬入時要留意換行符。
- 少女頁面首次載入需下載約 5.3 MB 的模型；模型與套件的授權都允許商用與再散布，套件的授權聲明需隨附。
- 實作前請先切到功能分支，目前在 `main`。
